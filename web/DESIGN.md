# DESIGN.md — 좌석 예약 데모

이 파일이 화면의 기준이다. 새 화면을 만들 때 여기 없는 값을 즉석에서 정하지 않는다.

## 기준을 바꿨다 (2026-08-07)

처음에는 **DICE.fm**을 실측해 기준으로 삼았다. 그런데 만들어 놓고 보니
"기능 테스트 화면"으로 보였고, 이유가 분명하지 않았다.

국내 예매 서비스를 실제로 재 보고 나서 알았다. **DICE는 지정석을 파는 서비스가 아니다.**
공연을 소개하고 한 종류의 티켓을 파는 곳이다. 그 언어(거대 활자·각진 면·넓은 여백)를
좌석을 고르고 돈을 내는 화면에 씌워 놓았던 것이다.

### 진단

**포스터가 화면을 지배하는데 우리에겐 이미지가 하나도 없었다.** 그게 전부였다.
좌석표를 아무리 정교하게 그려도, 공연을 고르는 화면에 그림이 없으면 예매 서비스로 보이지 않는다.

DICE에서 가져온 강한 활자는 버리지 않았다 — **포스터 타일 안에서 산다.**

## 왜 이 방향인가

좌석 예매는 **초 단위로 결정하는 화면**이다. 지금 눌러야 할 것이 무엇인지가
한눈에 보여야 한다 — 액센트를 하나만 쓰는 이유다.

포트폴리오의 다른 프로젝트와도 겹치지 않아야 한다.
FinMate는 밝은 민트 클레이 모바일, 실시간 채팅은 조밀한 다크 프로툴이다.

## 토큰

```css
--ink:      #0a0a0a;   /* 글자·검정 면 */
--paper:    #f7f6f3;   /* 배경. 순백이 아니라 인쇄지 쪽으로 */
--white:    #ffffff;
--muted:    #6b6862;   /* 보조 글자 */
--line:     #d8d5cf;   /* 경계선 */
--volt:     #d8ff2e;   /* 액센트. 형광 옐로그린 — 검정 위에서만 쓴다 */
--sold:     #b8b4ac;   /* 판매 완료 좌석 */
--danger:   #c2381f;   /* 실패·만료 */
```

**액센트는 하나뿐이다.** `--volt`는 "지금 눌러야 할 것" 한 곳에만 쓴다.
한 화면에 두 개 이상 있으면 둘 다 눈에 안 들어온다.

대비: `--volt` 위 글자는 반드시 `--ink`. 흰 배경 위에 `--volt` 글자를 쓰지 않는다(1.7:1).

> **배경은 실측과 다르다.** 두 서비스 모두 순백이지만 우리는 인쇄지 쪽(`#f7f6f3`)을 유지한다.
> "바이브 코딩 UI"의 원인은 배경색이 아니라 이미지 부재와 96px 활자였고, 그 둘은 고쳤다.
> 종이 톤은 이 데모의 남은 성격이다 — 일부러 남긴 차이라고 적어 둔다.

## 타이포

Pretendard를 시스템 스택으로 쓴다.

| 토큰 | 크기 | 쓰는 곳 |
|---|---|---|
| `--fs-page` | **28px** | 페이지·섹션 제목. **가장 큰 글자** |
| `--fs-sub` | 20px | 하위 제목 |
| `--fs-title` | 17px | 카드 제목·포스터 활자 |
| `--fs-body` | 15px | 본문 |
| `--fs-small` | 13px | 보조 |
| `--fs-label` | 12px | 라벨·버튼. 자간 0.08em |
| `--fs-badge` | 11px | 상태 배지 |
| `--fs-focus` | clamp(56px, 11vw, 72px) | 대기 순번·남은 시간 |

**굵기는 400과 700 두 단계다.** 실측한 두 서비스 모두 그랬다.

`--fs-focus`만 28px 규칙에서 벗어난다. 이건 제목이 아니라 **계기판**이다 —
사람이 응시하는 숫자는 대기 순번과 결제 남은 시간 둘뿐이다.
전에는 대기 순번이 384px이었다.

화면에서 `clamp()`를 새로 쓰지 않는다. 여기 없는 크기가 필요하면 대개 크기가 아니라 배치 문제다.

## 레이아웃

```css
--gutter: max(4vw, calc((100% - 1200px) / 2));
```

- 본문 폭 **1200px**. 좁으면 4vw 여백이 이기고, 넓어지면 1200px에서 멈추고 가운데로 온다
- 머리글·바닥글까지 같은 값을 쓴다. 한 곳만 다르면 세로선이 어긋난다
- 모서리 **8px**(`--radius`) · 칩과 배지는 6px(`--radius-sm`) · 버튼은 알약
- 경계선은 1px `--line`. 그림자를 쓰지 않는다 — 종이는 뜨지 않는다

**좌석만 각지다**(`border-radius: 0`). 둥글리면 도면이 아니라 아이콘으로 읽힌다.

## 배너 캐러셀

목록 맨 위. `web/scripts/generate-banners.mjs`가 만들고 `public/banners/CREDITS.md`에 출처가 있다.

### 실측 (NOL 티켓, 2026-08-07)

| | 값 |
|---|---|
| 배너 | 1425×463 = **3.08:1** · full-bleed |
| 자동 전환 | 2500ms · 전환 300ms · 무한 루프 |
| 슬라이드 | 17장 |
| 썸네일 | **52×52 정사각** · 간격 8px · 모서리 6px · 슬라이드당 1개 |
| 스트립 | 본문 폭(1280px)에 맞춰 배너 하단에서 40px 띄워 겹침 |

### 포스터는 실사, 배너는 생성물

같은 공연에 그림이 둘 있고 성격이 다르다.

**NOL의 배너는 글자까지 구워진 일러스트 한 장이다.** 활성 슬라이드의 텍스트 노드가
**0개**였고 `<img alt="뮤지컬 〈광화문연가〉">` 하나뿐이었다. 사진을 잘라 넣은 것이 아니라
배너 비율로 그린 그림이다.

3:4 세로 사진을 3:1로 자르면 그 흉내가 된다. 우리 사진 여섯 장 중 둘(ORBITAL WEEKEND ·
LOW TIDE)은 세로라 잘라 봐야 얇은 띠만 남는다. 그래서 **배너만 생성물로 간다.**

**글자는 여전히 굽지 않는다.** 주제를 오른쪽에 몰고 왼쪽을 비우도록 그려서 그 자리에
HTML 활자를 얹는다. 그림은 `alt=""`다 — 공연명은 바로 옆에 진짜 활자로 있다.

### 스크림 세기는 최악 픽셀로 정했다

활자 자리에 같은 방향의 막을 깐다. 어두운 그림은 `rgba(6,8,12,.78 → .52)`,
밝은 그림은 `rgba(255,253,248,.82 → .56)`, 가로 68%에서 사라진다.

**평균 휘도로 고르면 틀린다.** 처음엔 그림 왼쪽 45%의 평균을 재서 흰 글자 5.7~16.8:1이
나왔길래 넉넉하다고 봤다. 그런데 활자가 실제로 놓이는 상자(가로 12~30% · 세로 29~44%)의
**최악 픽셀**로 다시 재니 막이 없을 때 이랬다.

| | 막 없음 | .62 | **.78** | .88 |
|---|---|---|---|---|
| 밤의 라디오 | **1.3:1** | 4.3 | **7.4** | 10.4 |
| CROSSFADE 2026 | **1.0:1** | 3.4 | **5.9** | 8.4 |
| NOCTURNE — SEOUL | 3.7:1 | 9.8 | **13.4** | 15.8 |

달과 해가 정확히 글자 뒤에 있었다. 평균만 봤으면 읽을 수 없는 화면을 내보냈을 것이다.
`.72`에서 최악이 4.8:1이라 여유를 두고 `.78`로 잡았다. **여섯 장 전부 5.9:1 이상.**

### 자동 전환은 5초다 (실측은 2.5초)

NOL은 슬라이드가 17장이라 빨리 돌아야 한 바퀴가 돈다. 우리는 6장이고 5초면 한 바퀴 30초다.
읽고 판단할 시간을 준다 — 자동으로 움직이는 것은 느릴수록 덜 적대적이다.
**실측과 다른 값이므로 여기 적어 둔다.**

### NOL에 없는 것을 더했다

그쪽 캐러셀에는 **정지 버튼이 없고 썸네일이 `<div>`라 키보드로 닿지 않는다** —
WCAG 2.2.2(Pause, Stop, Hide)와 4.1.2 위반이다. 기준으로 삼되 고장난 부분까지 따라가지 않는다.

- 정지·재생 버튼. 자동으로 움직이는 것에는 멈출 방법이 있어야 한다
- 썸네일이 진짜 `<button>`이고 `aria-current`로 지금 위치를 말한다
- 마우스를 올리거나 포커스가 안에 들어오면 멈춘다
- `prefers-reduced-motion: reduce`이면 **자동 전환을 아예 시작하지 않는다.**
  CSS로 전환만 0으로 만드는 것으로는 부족하다 — 5초마다 화면이 바뀌는 것 자체가 문제다.
  이때는 정지 버튼도 두지 않는다(멈출 것이 없다)
- `aria-live`를 쓰지 않는다. 5초마다 낭독하면 방해가 된다
- 보이지 않는 슬라이드는 `inert`. 복제까지 8칸이라 그냥 두면 안 보이는 링크 7개가 탭에 걸린다

### 배경 탭에서 무너졌다

무한 루프는 앞뒤에 복제를 한 장씩 두고 끝에 닿으면 제자리로 되돌리는 방식이다.
처음엔 되돌리는 시점을 `transitionend`로 잡았는데, **배경 탭에서는 CSS 전환이 돌지 않아
그 이벤트가 오지 않는다.** `setInterval`은 계속 뛰므로 인덱스만 커졌다 —
탭을 두고 다른 일을 하다 돌아왔더니 14까지 가서 배너가 화면 밖에 있었다.

지금은 두 가지로 막는다. **타이머로 되돌리고**(어느 상태에서든 뛴다),
**탭이 배경으로 가면 자동 전환을 멈춘다**(`visibilitychange`).
감소 모션에서도 지속 시간이 0이라 `transitionend`가 오지 않으므로 같은 이유로 타이머여야 한다.

## 컴포넌트

**버튼**

| 종류 | 생김새 |
|---|---|
| primary | 검정 채움 · `--volt` 글자 · 알약 · `--fs-label` |
| secondary | 투명 · 1px `--ink` 테두리 · 알약 |

높이 44px 이상(터치 목표). `:focus-visible`에 2px `--ink` 외곽선을 **항상** 둔다.
검정 면 위에서는 뒤집는다 — 검정 배경에 검정 버튼을 두면 사라진다(실제로 그랬다).

**상태 배지**

색만으로 말하지 않는다. 글자가 상태를 그대로 적는다(예매중 · 매진임박 · 매진).

**좌석**

| 상태 | 면 | 테두리 |
|---|---|---|
| 선택 가능 | `--white` | 1px `--line` |
| 선택함 | `--ink` | 2px `--ink` |
| 판매 완료 | `--sold` | 없음 |

`aria-label`에 "선택 가능/선택함/예매 완료"를 넣는다.

## 모션

- 기본 180ms `cubic-bezier(0.2, 0, 0, 1)`
- 좌석 선택은 **즉시**(0ms). 눌렀는데 늦게 반응하면 두 번 누른다
- 카드에 마우스를 올리면 **포스터만** 1.03배가 된다. 카드 전체를 띄우면 격자가 출렁인다
- 배너는 5초마다 넘어간다. 정지 버튼이 있고, 마우스·포커스·배경 탭에서 멈춘다
- `prefers-reduced-motion: reduce`에서 전부 끈다. 페이드가 아니라 진짜 0으로.
  배너는 CSS만으로 부족해 자동 전환 자체를 시작하지 않는다

## 접근성

- 대비 4.5:1 이상. `--muted`(#6b6862)는 `--paper` 위에서 4.9:1
- 배지 안에서는 `--muted`가 4.4:1이라 한 단계 어둡게 쓴다(#56524c)
- 그림 위 활자는 **평균이 아니라 최악 픽셀**로 잰다. 평균으로는 전부 통과했지만
  최악 픽셀로는 배너 두 장이 1.0~1.3:1이었다
- 색만으로 상태를 말하지 않는다 (좌석·전달 상태·배지 모두)
- `web/e2e/booking.spec.ts`가 axe로 검사한다. **이 파일을 깨지 않는 것이 재작성의 성공 기준이다**
- 좌석표는 키보드로 순회 가능해야 한다

## 좌석표 (2026-08-07)

좌석 화면은 **둘러보는 화면이 아니라 거래하는 화면**이다.
여기서는 좌석표가 주인공이라 머리글을 한 줄로 접었다.

| 값 | 이유 |
|---|---|
| 좌석 **28×28px** · 간격 4px | 20석 열이 한 줄에 들어가면서 목표 크기 24px은 넘는 크기. 전에는 44px에 8px 간격이라 20석 열이 940px를 넘어 두 줄로 접혔다 |
| 구역 순서 = **가격 내림차순** | 좌석표에서 위아래는 무대와의 거리다. API는 구역을 이름순으로 주므로 그대로 그리면 가장 싼 A구역이 무대 바로 아래에 온다 |
| 가운데 통로 18px | 통로가 없으면 격자로만 보이고 어디가 가운데인지 읽히지 않는다 |
| 판매 완료는 채움만 | 28px에서 취소선은 읽히지 않고 얼룩으로 보인다. `aria-label`에는 "예매 완료"가 그대로 있다 |
| 좁은 화면은 **가로 스크롤** | 20석 열은 폰 너비에 안 들어간다. 열을 접으면 도면이 아니라 격자가 된다 |

> 이 수치들은 **실측이 아니라 관례**다. 국내 예매 서비스의 좌석표는 로그인·예매 세션
> 안에 있어 열 수 없었다. 재려면 남의 서비스에서 실제로 예매를 진행해야 하고,
> 그건 할 일이 아니다. 잰 것처럼 적지 않는다.

### 데이터가 화면을 만든다

회차당 50석(VIP 10 · A 20 · B 20)일 때는 무엇을 어떻게 그려도 테스트 픽스처로 보였다.
공연장을 제대로 짓고 나서야 좌석표가 좌석표가 됐다 — 구역 4개 436석,
그리고 **일부는 이미 팔려 있다.** 전 좌석이 비어 있는 예매 화면은 존재하지 않는다.

판매 상태는 회차 id로 시드를 고정해 만든다. 좋은 자리부터, 공연이 가까울수록 많이 빠진다.

같은 진단이 목록 화면에도 그대로 걸렸다. 포스터가 없으면 무엇을 어떻게 배치해도
예매 서비스로 보이지 않는다. **화면의 문제가 데이터의 문제인 경우가 많다.**

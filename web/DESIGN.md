## 왜 이 방향인가

공연 티켓은 **포스터**다. 정보를 조밀하게 늘어놓는 화면이 아니라, 한 장면이 크게 서고
나머지가 그 밑에 작게 붙는 구조다. 그리고 좌석 예매는 **초 단위로 결정하는 화면**이라
지금 눌러야 할 것이 무엇인지가 한눈에 보여야 한다 — 액센트를 하나만 쓰는 이유다.

포트폴리오의 다른 프로젝트와도 겹치지 않아야 한다.
FinMate는 밝은 민트 클레이 모바일, 실시간 채팅은 조밀한 다크 프로툴이다.
여기는 **흑백 포스터**다.

## 토큰

```css
--ink:      #0a0a0a;   /* 글자·검정 면 */
--paper:    #f7f6f3;   /* 배경. 순백이 아니라 인쇄지 쪽으로 */
--white:    #ffffff;
--muted:    #6b6862;   /* 보조 글자 */
--line:     #d8d5cf;   /* 경계선 */
--volt:     #d8ff2e;   /* 액센트. 형광 옐로그린 — 검정 위에서만 쓴다 */
--sold:     #b8b4ac;   /* 판매 완료 좌석 */
--danger:   #c2381f;   /* 실패·만료 */
```

**액센트는 하나뿐이다.** `--volt`는 "지금 눌러야 할 것" 한 곳에만 쓴다.
한 화면에 두 개 이상 있으면 둘 다 눈에 안 들어온다.

대비: `--volt` 위 글자는 반드시 `--ink`. 흰 배경 위에 `--volt` 글자를 쓰지 않는다(1.7:1).

## 타이포

Pretendard를 시스템 스택으로 쓴다. 한글이 필요하므로 라틴 전용 압축 서체는 쓰지 않고,
**900 굵기 + 좁은 자간 + 촘촘한 행간**으로 같은 인상을 만든다.

| 이름 | 크기 | 굵기 | 자간 | 행간 | 쓰는 곳 |
|---|---|---|---|---|---|
| `.display` | clamp(56px, 11vw, 128px) | 900 | -0.04em | 0.86 | 화면 제목 하나 |
| `.headline` | clamp(28px, 4vw, 44px) | 800 | -0.03em | 1.0 | 섹션 |
| `.title` | 20px | 700 | -0.01em | 1.3 | 카드 제목 |
| `.body` | 15px | 400 | 0 | 1.6 | 본문 |
| `.label` | 12px | 700 | **0.08em** | 1 | 라벨·버튼. 대문자/괄호 표기 |
| `.mono` | 13px | 500 | 0 | 1.5 | 좌석 번호·금액·시각 |

디스플레이는 **한 화면에 하나만** 쓴다. 둘 이상이면 위계가 사라진다.

## 레이아웃

- 최대 폭 1200px, 좌우 여백 24px (모바일 16px)
- 세로 리듬 8px 배수
- 카드는 **모서리를 둥글리지 않는다**(`border-radius: 0`). 포스터의 인상이 여기서 나온다.
  예외는 알약 버튼과 상태 칩
- 경계선은 1px `--line`. 그림자를 쓰지 않는다 — 종이는 뜨지 않는다

## 컴포넌트

**버튼**

| 종류 | 생김새 |
|---|---|
| primary | 검정 채움 · `--volt` 글자 · 알약 · `.label` |
| secondary | 투명 · 1px `--ink` 테두리 · 알약 |
| ghost | 밑줄만 |

높이 44px 이상(터치 목표). `:focus-visible`에 2px `--ink` 외곽선을 **항상** 둔다.

**좌석**

정사각형 32px, 모서리 각짐. 상태는 색만으로 구분하지 않는다 —
`aria-label`에 "선택 가능/선택함/판매 완료"를 넣고, 선택함은 채움 + 굵은 테두리 둘 다 준다.

| 상태 | 면 | 테두리 |
|---|---|---|
| 선택 가능 | `--white` | 1px `--line` |
| 선택함 | `--ink` | 2px `--ink` |
| 판매 완료 | `--sold` | 없음 |

**대기실**

이 화면만 배경이 `--ink`다. 대기는 다른 시간이라는 인상을 주고,
`--volt` 하나가 거기서 가장 밝다.

## 모션

- 기본 180ms `cubic-bezier(0.2, 0, 0, 1)`
- 좌석 선택은 **즉시**(0ms). 눌렀는데 늦게 반응하면 두 번 누른다
- `prefers-reduced-motion: reduce`에서 전부 끈다. 페이드가 아니라 진짜 0으로

## 접근성

- 대비 4.5:1 이상. `--muted`(#6b6862)는 `--paper` 위에서 4.9:1
- 색만으로 상태를 말하지 않는다 (좌석·전달 상태 모두)
- `web/e2e/booking.spec.ts`가 axe로 검사한다. **이 파일을 깨지 않는 것이 재작성의 성공 기준이다**
- 좌석표는 키보드로 순회 가능해야 한다

## 좌석표 (2026-08-07)

좌석 화면은 **둘러보는 화면이 아니라 거래하는 화면**이다. 포스터 활자(최대 96px)는
목록·상세의 것이고, 여기서는 좌석표가 주인공이라 머리글을 한 줄로 접었다.
전에는 제목만으로 화면 절반을 먹어 좌석표가 잘렸다.

| 값 | 이유 |
|---|---|
| 좌석 **28×28px** · 간격 4px | 20석 열이 한 줄에 들어가면서 목표 크기 24px은 넘는 크기. 전에는 44px에 8px 간격이라 20석 열이 940px를 넘어 두 줄로 접혔다 |
| 구역 순서 = **가격 내림차순** | 좌석표에서 위아래는 무대와의 거리다. API는 구역을 이름순으로 주므로 그대로 그리면 가장 싼 A구역이 무대 바로 아래에 온다 |
| 가운데 통로 18px | 통로가 없으면 격자로만 보이고 어디가 가운데인지 읽히지 않는다 |
| 판매 완료는 채움만 | 28px에서 취소선은 읽히지 않고 얼룩으로 보인다. `aria-label`에는 "예매 완료"가 그대로 있다 |
| 좁은 화면은 **가로 스크롤** | 20석 열은 폰 너비에 안 들어간다. 열을 접으면 도면이 아니라 격자가 된다 |

> 이 수치들은 **실측이 아니라 관례**다. DICE.fm은 지정석 도면이 없어 잴 것이 없었고,
> 국내 예매 서비스의 좌석표는 로그인·예매 세션 안에 있어 접근할 수 없었다.
> 잰 것처럼 적지 않는다.

### 데이터가 화면을 만든다

회차당 50석(VIP 10 · A 20 · B 20)일 때는 무엇을 어떻게 그려도 테스트 픽스처로 보였다.
공연장을 제대로 짓고 나서야 좌석표가 좌석표가 됐다 — 구역 4개 436석,
그리고 **일부는 이미 팔려 있다.** 전 좌석이 비어 있는 예매 화면은 존재하지 않는다.

판매 상태는 회차 id로 시드를 고정해 만든다. 좋은 자리부터, 공연이 가까울수록 많이 빠진다.
